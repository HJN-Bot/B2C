# Spike · 要不要继续投入 SpeakPeak（go / no-go 验证）— 2026-07-26

> 这是一次**时间盒探索**，不是要立刻加功能。目的：用最低成本拿到能支撑"继续 / 暂停"
> 决定的信号。Owner 明确"对此事的评估需要先想一下"——本 spike 就是把那次评估变成可执行的验证。

## 目的
用最省的方式回答一个问题：**这个项目值不值得 Owner 继续投入时间？**
不靠"再写一版计划"或"先把基建/后端搞漂亮"来回避，而是拿真实用户信号来判。

## 核心假设（待验）
有演讲 / 辩论目标的中学生（及买单的家长）会觉得 SpeakPeak 的"练完教你说得漂亮"
有**真实价值**，愿意持续用、甚至愿意付费。

## 前置：先让产品配得上被推（低成本、纯打磨）
1. **修 Takeaway 复盘页 AI 反馈质量**（4 项，spec 见 `2026-07-13-takeaway-fixes.md`）——
   反馈不笼统、金句是"你自己原话的改写"、追问针对本次内容、不每次重生成。
2. **换 AI API 到 DeepSeek**（OpenAI 兼容）——降成本、国内更稳，为群内国内用户体验兜底。
   （改 `supabase/functions/gemini-proxy`，本机无 supabase CLI，部署交 Owner。）

## 最小验证动作（IP 化，零国内基建）
- Owner 用**自己的小红书**发 1–2 条场景 A 内容（辩论 / 演讲陪练），挂 **Vercel 链接**（够用）。
- 在**现有群**拉一个小试用群，投链接 + 一句引导（如"练完把复盘截图发群里"）。
- 收集：谁真的练了、练了几次、复盘对他有没有用、有没有人主动问"能不能一直用 / 多少钱"。

## 判定信号（阈值请 Owner 定）
- **Go（继续）**：出现 ≥1 个"愿持续用 + 愿为结果付费"的真实信号；或一批学生自发多次练习。
- **No / Pivot**：投了链接但没人真用、或用了觉得没价值 → 停下重想切口，
  **而不是**继续加功能 / 砸基建。

## 明确不做（押后到 Go 之后）
.cn 备案、自建 Supabase、微信小程序、视频号矩阵。验证阶段一个 Vercel 链接就够。

## 时间盒
产品修复 ≈ 几天；IP 化试水 ≈ 1–2 周观察窗口。

## Owner 待定项
试用群规模 N、观察窗口长度、"算作信号"的具体阈值（几人？几次？一句愿付？）。
