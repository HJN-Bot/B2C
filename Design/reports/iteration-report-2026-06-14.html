D

后端与存储规划 + 决策项

现状：没有登录系统（"Alex" 是写死的 mock），历史 / 短语 / prompt 偏好都只存在本机 localStorage（换设备、清缓存即丢，且不绑定到任何用户）。要做"和用户绑定 + 跨设备 + 录音回放"，需要后端。

要存什么（按用户 / 按 session）

数据现在是否需要后端
用户账号（who，admin）mock "Alex"需 Auth 登录 — 一切的锚点
练习 session（时间/模式/时长/分数）localStorage，单设备需 sessions 表（按 user）
Transcript（你说了什么）存在 session 里（本机）随 session 存后端
音频录音不录、不存需录音 + Supabase Storage（音频桶），关联 session
历史 coach（每次的 AI 问答 / takeaway）每次重生成、不保存按 session 存，才能回看
短语库 / trying point / prompt 偏好本机推导/存储按 user 存（跨设备）
前端界面 / 交互已完成不需后端

用户 admin 与多 session 怎么分

一切以 user_id（来自登录）为根：每个用户只看到自己的数据（行级权限 RLS）。每次练习 = 一条 sessions 行（id · user_id · 时间 · 模式 · 时长 · 分数 · transcript · audio_path），其下挂 highlights、coach_messages（外键 session_id）。所谓"用户 admin" = 现在缺失的登录/账号层。

决策项（请团队拍板）

  • 是否现在做真正的登录 / 账号（auth）？这是"绑定用户 + 跨设备 + 录音"的前提。不做就维持单设备 localStorage（够 demo）。
  • 音频要不要录 + 存？面向 11–15 岁未成年人，涉及隐私 / 同意 / 存储成本。或先只存 transcript、不做回放。
  • 后端用哪个：恢复旧 Supabase 项目，还是新建？需建 Postgres 表（sessions/highlights/coach_messages）+ Storage 桶 + RLS。
  • 数据保留 / 隐私：未成年人数据（尤其音频）的留存期、同意、删除机制。
  • 额度 / 成本：Gemini 调用与存储的配额、谁承担、限额策略。

✅ 后台状态：已恢复

Supabase 后台已恢复，AI（实时教练 / takeaway 总结 / Coach 问答）已跑通可演示。上面的存储 / 账号 / 录音项是"要不要更进一步绑定用户、做跨设备"的决策，与当前可用性无关。详细操作见单独的 User Guidance。

下一步 / V3 路线图

持续迭代中。按优先级排，逐步推进。

  • 🔴 真账号体系（auth）+ 落库：Supabase Auth → user_id + RLS；sessions/highlights/coach_messages 入库（替 localStorage）。一切跨设备/绑定用户的前提。
  • 🔴 录音 + 未成年人合规：是否录/存音频（Storage）、同意/留存/删除——先决定再做。
  • 🟡 移动端语音识别：浏览器 STT 不支持移动 Safari → 走服务端 STT（仓库已有 analyze-voice 雏形）或接第三方（Deepgram/Whisper）。
  • 🟡 KTV 计分校准：现为本地启发式（IELTS/TOEFL 维度方向对、分数未校准）→ 真人录音校准 或 改 AI 评分。
  • 🟡 部署 gemini-proxy：让"实时调用关 thinking 提速"真正生效（代码已就绪）。
  • 🟡 暂停卡片延迟优化：继续提高预生成命中率、缩短 prompt、并行请求或流式返回，让停顿后的追问更快出现。
  • 🟢 埋点 / 分析：后台记录行为事件看漏斗/留存；用真实证据做正向反馈，不用压力型 streak。
